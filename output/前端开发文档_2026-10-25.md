## 0. 范围与原则

| 项 | 决议 |
|---|---|
| 现状 | Streamlit 多页应用 `ui/`，13 页 + 首页 ≈6,900 行 |
| 目标 | 10 个静态 HTML 页 + FastAPI 只读服务，`core/` 业务层**不动** |
| 双轨策略 | 新前端上线前 `ui/` 保持可运行；按页面灰度，不做大爆炸切换 |
| 非目标 | 不做组件框架迁移；不做 SSR；不做多用户 |

三条不可协商的原则（继承项目铁律）：

1. **失败必须分区可见**：任一数据源不可用时**该区块**显示 `不可用` 及原因类型，绝不返回 0、绝不留空假装正常。
2. **数据日期与查询时间分离**：页面所有数值必须能回答"这是哪一天的数据"，快照类一律标注截止日期。
3. **测试跟着页面走**：每迁移一页，**新增**该页端点的契约测试；既有 UI 测试保留到该页真正下线（见 §7）。

## 1. 架构

```
┌────────────────────────────────────────────┐
│ 浏览器 · 10 个静态页（本地服务同源）          │
│   fetch('/api/*') · WebSocket（仅助手页）      │
├────────────────────────────────────────────┤
│ FastAPI  web/server/app.py                  │
│   · 只读端点（GET）                          │
│   · 写操作转发（POST → 现有任务队列）          │
│   · 统一超时包裹 / 缓存 / 分区错误口径        │
├────────────────────────────────────────────┤
│ core/ + data/ + db/（现有业务层，不改）        │
│   screener · agents · portfolio · ai_league  │
│   news_feed · zhihu_opinions · sentiment_ref │
├────────────────────────────────────────────┤
│ data/portfolio.db · output/ · config/       │
└────────────────────────────────────────────┘
```

**为什么这样分**：

- exe 只需打包「FastAPI + 浏览器窗口」，不必把 Streamlit 运行时塞进 PyInstaller（体积与启动时间差一个数量级）。
- 重依赖（`akshare` 冷导入 ≈4s、`core.news_industry_review` ≈9.3s）由**常驻服务**一次承担，页面切换零导入成本——这正式 Streamlit 版 10-15 实测"切换慢"的根因。
- 静态页无状态，任何页面可独立开发、独立测试、独立替换。

**FastAPI 服务职责边界**：只做取数、整形、缓存、错误口径；**不做业务决策**。所有筛选/评分/判定逻辑仍由 `core/` 提供，服务层禁止第二套实现。

**依赖现状（2026-10-25 实测，系统 Python 3.12）**：`uvicorn` ✅ 已装 · `apscheduler` ✅ · `pytest` ✅ · **`fastapi` 已声明未安装**（`requirements.txt` L30 `fastapi>=0.115.0`，10-25 补入；本机 `import fastapi` 仍失败） · `pywebview` ❌（P6 才需要）。
⇒ P1 第一步：`pip install -r requirements.txt`，否则 `uvicorn web.server.app:app` 直接 ImportError。

### 2.1 深度分析页：回看与往期胜率

2026-10-25 的用户反馈原文是 **"深度分析报告无法回看，往期胜率也没办法回看"**。根因不是功能没写，而是**两端都没接线**：`db.store.get_analysis()` 与 `core.analysis_review.aggregate_recent()` 早已存在且有单测，但既没有 HTTP 端点、页面历史列表也只是纯文本（还 `slice(0, 8)` 截断到 8 条）。现在补齐为：

| 能力 | 实现要点 |
|---|---|
| 点历史条目看完整报告 | `GET /api/analysis/detail/{ana_id}` → **同一个** `applySnapshot()` 渲染器（走 `tech_report`/`fundamental_report`/`news_report`/`research_summary`/`final_decision` + 多空辩论 + 审计 + 决策卡），与"刚跑完"完全一致 |
| 回看态不被实时覆盖 | 回看时 `stopPolling()`；否则 2s 一次的轮询快照会盖掉历史，表现成"点了闪一下又变回去" |
| 事后结果 | 只在回看里显示 `T+5 / T+20 / 达标 / 止损`；实时分析还没走完窗口，本来就没有这些数 |
| 往期胜率 | `GET /api/analysis/stats?days=180&horizon=5\|20`；页面按 T+5 / T+20 切换 |
| 历史列表 | `limit=200` 全量、可滚动、**不再按 `code` 过滤**（回看要的是"任何一条都能打开"） |

**胜率口径（三条都踩过）**：

1. **分母 = 判出方向的条数**。观望/驳回（`no_position`）单列、**不进分母** —— 否则"全观望"会显示成 **0% 胜率**，而它是"没预测"，不是"猜错了"。
2. `unclear`（±3% 内没走出来）**进分母但既不算对也不算错**，页面单列。并进"判错"会让胜率虚低，并进"判对"是在改事实。
3. `win_rate_pct` 为 **`null` 表示"还没有可判定的样本"**，不是 `0%`（"缺就是缺"）。

**为什么样本会显得少**：复盘样本由 T+N 窗口决定 —— 一条分析要等 5 / 20 个**交易日**才进统计。分析历史最早只到 2026-10-09，到本日仅 11 个交易日 ⇒ T+5 有 16 条、**T+20 必然是 0 条**。这是时间状态，不是回填坏了（实测 `backfill_analyses` 返回 `checked:1, not_ready:1`）。
排查时别被 `runs` 表里 `job:backfill_analysis` 的 `stats.checked = 0` 误导：那是历史旧记录，当前实现返回的是 `{"checked", "not_ready", "unavailable", "done", "partial", "failed", ...}` 全套键；**真判断要看 `not_ready` 与 `unavailable` 分桶**，两者含义完全不同（"窗口没走完" vs "取数失败"）。

## 4. API 契约

### 4.1 通用约定

- 只读 `GET`；写操作（选股执行、知乎采集、下单、保存话题）走 `POST`，内部转**现有任务队列**（`core/ui_tasks.py`），前端轮询任务态——不新造第二套任务机制。
- 顶层包络：`{"ok": true, "data": ..., "as_of": "数据日期", "fetched_at": "查询时间"}`；顶层 `ok=false` **仅表示服务本身故障**（进程异常），与数据无关。
- **分区包络（C2）**：聚合类端点（dashboard）的每个子区自带 `{ok, data, as_of, error:{type}}`。任一子区失败**不得**把顶层 `ok` 置 false——否则整页"不可用"，直接违反 §0 原则 1。
- **错误口径**：`error.type` 取值 `timeout | auth | proxy | empty | stale | missing | not_implemented`；绝不返回 0、绝不返空表冒充正常。`missing`（文件不存在，"没跑"）与 `empty`（文件在但解析失败，"坏了"）必须区分——排查方向完全不同。
- 服务层统一超时包裹（`akshare` 取数无内置超时，是既知挂起坑）：默认 6s，快讯类 10s。
- 缓存：进程内 TTL + **键 = 页面 + 作用域（账户名）+ `as_of`**。只带页面和账户不够——跨日会把昨天数据当今天（项目踩过）。
- 快照类端点必须带 `stale` 标记与数据截止日期（如指数"新浪收盘后只到 T-1"）。

### 4.2 端点一览

> **48 个路径 / 53 个操作**（52 条 HTTP + 1 条 WebSocket）。下表一行一个路径，共 48 行；
> 5 个路径挂双 method 所以行数 < 操作数：`GET+POST /api/analysis/{code}`、
> `GET+POST /api/chat/sessions`、`GET+DELETE /api/chat/sessions/{session_id}`、
> `GET+POST /api/watch/watchlist`（2026-10-27 加写入）、`GET+POST /api/system/models`（同日加写入）。
> ⚠️ **别用 `app.openapi()` 数端点**：本版 FastAPI 的 `app.routes` 里装的是 10 个 `_IncludedRouter`
> 惰性对象（`path` 为空），`openapi()` 只吐出 `/api/docs`、`/api/openapi.json` 这 2 条自带路由，
> 据此会得出"只有 2 个端点"或"4 paths"。正确姿势是遍历 `web.server.routers` 下每个模块的
> `router.routes` 按 `methods` 有无区分 HTTP/WS（脚本见 §4.2 末）。
> **也别把 path 数当端点数**：42 是路径、47 才是操作数，两个数字都要说清，否则"少 3 个端点"的假警报会反复出现。
> ✅ = 已实装并有契约测试；无标记的只存在于早期设计稿（本文档已无此类行）。

| 端点 | 页 | 来源 | TTL | 备注 |
|---|---|---|---|---|
| `GET /api/meta` ✅ | 全部 | 服务自身 | 0 | 版本/启动时间/数据目录/是否离线/模板版本；页脚与系统页复用 |
| `GET /api/picks/latest` ✅ | 选股/仪表盘 | `output/daily_picks/latest.json` | 60s | 含 `date/mode/picks/market_signal/stage_timings`；`stale` 判据见 C3 |
| `GET /api/picks/options` ✅ | 选股 | `core.screener.STRATEGIES` + `SECTOR_HARDCODED` | — | 策略 + 板块清单（**前端下拉的唯一来源**，不在 JS 里写死一份） |

import importlib, pkgutil, web.server.routers as R
paths = {}
for m in pkgutil.iter_modules(R.__path__):
    rt = getattr(importlib.import_module('web.server.routers.'+m.name), 'router', None)
    if rt is None: continue
    for r in rt.routes:
        ms = getattr(r, 'methods', None)
        paths.setdefault(r.path, set()).update(ms if ms else {'WS'})
h = sum(1 for v in paths.values() for m in v if m != 'WS')
w = sum(1 for v in paths.values() for m in v if m == 'WS')
print(f'路径 {len(paths)} / 操作 {h+w} = HTTP {h} + WS {w}')"

### 4.3 数据形状铁律（C1/C3/C4，2026-10-25 已修代码）

**C1 `market_signal` 是对象，不是字符串（已修复）**

- 病史：`json.dump(default=str)` 把 `MarketSignal`（dataclass）打成 repr 文本（`MarketSignal(total_score=28.4, ...)`）⇒ 前端拿到一整串文本，`ai_daily_round` 只能用正则取三个数。
- 已修：`core/pipeline._json_default` 落盘前 `dataclasses.asdict()`；`core/ai_daily_round._load_market_signal` dict 直读 + 旧 repr 串正则回退（双格式，磁盘旧文件仍是串）；`ui/pages/1` 本就兼容 dict；`core/screen_history` 同步双格式。测试：`test_pipeline.py::test_market_signal_serialized_as_dict_not_repr` + `test_ai_daily_round.py::TestMarketSignalDualFormat`（3 例）。
- 契约：`/api/picks/latest` 的 `market_signal` 字段表 = `total_score / market_state / signal / position_limit / strategy_bias / operation_advice / scores / indicators / risk_warnings / timestamp`（与 `core/market_detector.MarketSignal` 逐字段对应）。
- ⚠️ **`_json_default` 对 `report` 内任何 dataclass 全局生效**：现在只有 `market_signal` 是 dataclass 所以安全；将来谁把别的 dataclass 塞进 report，它会**静默**从"repr 字符串"变成"dict"，消费方踩同一个坑（`ai_daily_round` 正则失配那种）。⇒ **report 内新增 dataclass 字段，必须同步检查全部消费方**（`core/`、`ui/`、将来的 `web/` 三处），并照 C1 加双格式测试。**禁止**再往 `default=str` 回退。
- ⚠️ **新旧格式并存期**：磁盘上的 `latest.json`（10-23 那份）仍是 repr 串。`/api/picks/latest` 读到旧格式时**显式返回 `format: "legacy"` + `stale: true`**，不在服务层静默归一化——让前端和排查都能一眼看见"这是旧文件"，而不是猜。

**C3 数据日期校验（照抄 `review_agent` 纪律，服务层不另写一套）**

- `latest.json` 实测当前是 **2026-10-23（周五）**。⚠️ **10-24 / 10-25 是周六周日，本就没有盘后流程**——latest 停在 10-23 是**正确状态，不是 stale**。`stale` 的基准必须是"最近应收盘的交易日"（10-25 当天 15:10 前算 10-23），**不是"今天"**：拿日期直接和 `today()` 比，会让每个周末都误报 stale，长期看等于闸门关掉。判据见 §4.1 的 C3，实现见 `web/server/picks.py`。
- `stale` 判据：非今天 / 文件 mtime 超过一个完整交易周期 / `mode` 与请求场景不符。
- `review_agent` 已有 `latest["date"] == today` 的判法，复用它，不造第二套。

**C4 字段名是中文，原样透传**

- `picks[]` 的键是 `股票代码 / 股票名称 / 板块 / 策略 / score / score_coverage`（与 `daily_picks/latest.json` 落盘一致）。**不转英文**（转译会让两套前端各有一套命名）；前端模板与 JS 一律按中文键写。
- 例外：服务层自产的元信息（`stale/error/as_of` 等）用英文键，与数据字段区分。

### 4.4 快讯端点细节（情报页，P2 已实现）

```
GET /api/intel/news?hours=24&limit=60&industry=科技&sentiment=positive
→ { ok, as_of, data: {
      window:   { hours, since, total, by_sentiment:{positive,negative,neutral} },
      filtered: { industry, sentiment, total, by_sentiment:{...} },
      items: [{ id, title, preview, sentiment, source, published_at,
                related_codes:[], sectors:[] }],
      returned, industries:[...], db:{total,latest,today}
  } }
```

**两层统计必须都返回**（这是 P2 的核心口径）：
- `window` = 时间窗内**全量**（不受筛选影响）；`filtered` = 当前筛选条件下。
  只给一个数，页面就会把"筛选后 46 条"说成"全市场 46 条"。
- `items` 上限 **300**（`limit` 上限保护），`hours` 上限 **720**（30 天）。
- `industry` / `sentiment` 传非法值 ⇒ `error.type = "invalid"` 并列出可选值。
  **不许静默返回全量**——那会被读成"这个行业今天没新闻"。
- 行业筛选在 **SQL 侧**生效（词表拼 `LIKE ... OR ...`），不是取一页再筛；
  否则分页数与 `filtered.total` 会互相矛盾。
- `title` 为空时从正文起头切 70 字当标题、`preview` 从切掉的位置继续（不重复同一句）。
  起因：**新浪源 `title` 是空串**（2026-10-25 实测 24h 窗口内 100+ 条），直接渲染就是一排空白行。
- `sectors` 是**检索口径**不是入库口径：`news_items` 无 `industry` 列，行业靠标题/正文命中词表实时归类。
- 热榜不在契约内：本机稳定 `ProxyError`，换源落地前不占端点。

**行业词表的唯一来源**：`data.news_feed._SECTOR_KEYWORDS`（服务层只 import，**不复制**）。
复制一份必然漂移——库内标签用旧词表、页面筛选用新词表，同一句话两个结论。

### 4.5 WS 事件契约（助手页，P4 已实现）

客户端连上 → 发**一条** JSON `{message, session_id?, persona?, model?}` → 服务端逐条推事件：

| `type` | 关键字段 | 前端动作 |
|---|---|---|
| `session` | `session_id` | 记录会话（新建时 URL 可回填）；**先于任何工具事件** |
| `tool_start` | `tool` / `args` | 渲染"进行中"chip（琥珀） |
| `tool_end` | `tool` / `summary`（一句话） | chip 打勾（青）+ `title` 显示摘要 |
| `chart` | `chart{kind:kline\|fund5, ...}` | 前端自己画（`closes` 折线 / 五维评分表） |
| `answer` | `text`（markdown 原文） | 与复盘共用 `bigaMd()` 渲染 |
| `error` | `error{type, message}` | 复用统一 `error.type` 枚举，红色 chip |
| `done` | `usage` / `tools` | **解锁输入框**；累加 tokens；刷新会话列表 |

**为什么是 WS 而不是 SSE**：前端中途要能发取消，且工具 chip 需要"开始/结束"两段状态，WS 的 send 语义更直接。
**为什么必须线程化**：见 §6 落地记录第 2 条（同步生成器 + 阻塞 HTTP）。
**失败也留痕**：本轮失败时用 `save_turn` 写入"（本轮失败：原因）"——比"这条对话消失了"可排查。
**LLM 输出不进主链**：只写 `chat_logs`，不写 `daily_picks` / 分析快照 / 决策表（AST 断言守着）。

服务启动：`python scripts/serve_web.py` → http://127.0.0.1:8765/（开发加 `--reload`）。

**为什么到 P3 才拆 routers/**：P2 时 9 个端点分 3 个业务域，一域一模块已经是最小可用分层，
再套一层目录只会把「端点 → 取数模块」的对应关系拆散。P3 加到 **17 个端点**后，
`app.py` 会退化成一张 300 行清单，于是按域拆成 `routers/{meta,picks,watch,intel,review,desk,research}.py`
——**路由层只搬运参数**，业务仍在 `<domain>.py`（这样端点再多，`app.py` 也只有装配逻辑）。
P4/P5 再加 `routers/{analysis,system,chat}.py`，`app.py` 仍是 10 行 `include_router`。

**复盘正文不转 HTML**：`/api/review/latest` 原样返回 markdown，前端用 40 行渲染器转义后渲染
（只支持报告里真实出现的语法：标题/引用/列表/表格/分隔线/粗体/行内代码/链接）。
理由：在服务层转 HTML 等于引入一个渲染器依赖，且注入面移到后端；放前端则转义与渲染同一处。

**三条实施期真问题**：

1. ⚠️⚠️ **`ui_runs.load_result()` 返回的是信封**（`{task,saved_ts,generated_at,payload}`），

   夹具必须同时 `monkeypatch.setattr(ur, "UI_RUNS_DIR", ...)`（默认参数/常量定义时求值的同一类坑）。

**打包冒烟挖出的两个 exe 专属问题**（源码运行永远看不到，只有真跑 exe 才暴露）：

## 8. exe 打包（**P6 已落地**，`scripts/{launch_exe,build_exe}.py`）

| 决策 | **落地事实**（2026-10-25 实测） |

| 模式 | PyInstaller **folder**（禁 onefile：每次启动解压 + 写入路径全改 + 杀软误报）。`build_exe.py` 里 `--onedir` 写死，`--onefile` 不提供 |

| **面板数据** | ⚠️ `data/panel/by_code` **387MB 不进包**：首次运行走正常回填/下载，**不能**混进"内置模板拷贝" |
| **单实例** | `acquire_os_mutex("web")`（`Global\` 前缀，跨会话）；第二次双击读 `data_root()/temp/web_port.txt` 定位已有实例并开窗口 |
| **退出清理** | 关窗口/`Ctrl+C` → `server.should_exit=True` → 等线程 5s → 超时 `os._exit(0)`。**无子进程**，所以不存在僵尸端口 |
| **静态资源** | `web/templates`、`web/static`、`config/*.json`（9 个）用 `--add-data` 打进 `_internal/` |
| **第三方数据** | `--collect-data akshare`：`akshare/file_fold/*.json` 必须进包（否则 `import akshare` 直接 FileNotFoundError，且交易日历会静默退化） |
| **密钥/环境** | `.env` **不进包**；打包态额外从 **exe 同级 `.env`** 读取（`config/settings.py` 的 frozen 分支）。缺它则助手/分析不可用，其余页面正常 |
| **调度器** | **随面板启动**（2026-10-26 改）：服务就绪后 `_spawn_scheduler()` 以 `DETACHED_PROCESS \| CREATE_NEW_PROCESS_GROUP` 起**独立进程**，已在跑则跳过（判据 = 心跳里的 **PID 是否活着**）。⚠️⚠️ frozen 下必须 `exe --scheduler` **自调用**——`sys.executable` 是 exe **自己**，拼 `[exe, "scripts/run_scheduler.py"]` 等于"用 exe 打开一个 .py"，noconsole 下**静默失败**（无窗口、无日志、无提示）。关面板**不停**调度器（选股/复盘是常驻职责，界面只是观察窗）；停止走 `停止bigAagents.bat`，已同步加 `--scheduler` 匹配规则。⚠️ 这与"调度器不挂**会话**后台"不冲突：那条约束的是**自动化会话**（被回收四次），用户双击所在的进程树不受影响 |

| **桌面快捷方式** | `assets/make_shortcut.py` 手写 `.lnk`（COM 被安全策略拦、符号链接要管理员）。⚠️⚠️ **`LinkTargetIDList` 是解析的必要条件**，见下 |
| 后续可选 | Nuitka（启动快 2×）——待 folder 版稳定后再评估 |

**相对本文档 v1.0 方案的两处偏离**（都已实测，理由写进 `launch_exe.py` docstring）：
1. **线程内 uvicorn 取代子进程**。原方案"子进程 + 关窗口杀进程组"要处理 Windows 进程组、
   僵尸端口、任务管理器残留——每一项都能让"关了窗口还在后台跑"。uvicorn 在非主线程
   不装信号处理器（自己判断 `current_thread() is main_thread()`），线程方案安全，进程退出即释放端口。
2. **控制台默认保留**（`--noconsole` 是可选开关）。第一版最需要"出错时能看见"；
   一开 `--noconsole`，导入失败就只剩闪退。

⚠️ **含密钥的 exe 不要分发**：`config/llm_providers.json` 进了包。要分发就用
`BIGA_LLM_PROVIDERS` / `BIGA_LLM_FEATURE_MODELS` 把配置外置到数据目录。
⚠️ **构建依赖独立**：`requirements-build.txt`（PyInstaller 6.6+，pywebview 可选），不进运行时 requirements。
⚠️ **重新打包要先过"批量删除闸门"**：`--noconfirm` 会先删 `dist/bigAagents`（约 2300 个文件），
在带安全删除钩子的环境里会以 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` **中止且退出码 1**，
而**旧产物还在**——看起来像"打包无声失败"。解法：`CODEBUDDY_SAFE_DELETE_ENABLED=0` 或先手工删目录。

⚠️⚠️ **旧 exe 正在运行时绝不能重打包**（2026-10-25 事故）：`COLLECT` 阶段先 `shutil.rmtree(dist/bigAagents)`，
若里面的 exe 被占用 ⇒ `PermissionError: [WinError 5]`，**而 rmtree 已把其余文件删光** ⇒ 留下
"只有 exe、没有 `_internal/`"的**残缺 onedir 目录**。这个目录能骗过 `os.path.exists(exe)`，
双击时 bootloader 找不到自己的 `_internal`，只弹一个标题为 **"Error"** 的系统框、
**一行 Python 都不执行、日志永远为空**——极易误判成"打包后启动失败"（本次为此浪费了一轮排查）。
现在两个方向都装了闸门：构建前 `_exe_locked()` 用 `open(exe,'r+b')` 探测占用并**拒绝构建**（退出码 3）；
构建后 `_verify_artifact()` **按内容校验**（必须有 `_internal/` 且文件数 ≥500），不只看 exe 存在。

⚠️⚠️ **手写 `.lnk` 必须带 `LinkTargetIDList`**（同日第二个事故）：省掉它时结构"完全自洽"
（HeaderSize 0x4C、CLSID 对、LinkInfo 各偏移自洽、`LocalBasePath` 能解出 `D:\桌面\...`、TerminalBlock 也在），
但双击报 **"没有应用程序与此操作的指定文件有关联"**——注意这句意思是"这不是快捷方式"，
不是"找不到目标"，很容易被当成系统关联坏了。隔离实验：拿安装程序生成的**正品 `.lnk`**，
① 原样 → 能启动；② **只清 `HasLinkTargetIDList` 标志位并删掉那段字节、其余一个不动** → 报同一个错。
⇒ IDList 是解析的必要条件，`LinkInfo` 只是缓存提示。生成规则：`[我的电脑 0x1F][卷 0x2F][逐级目录 0x31][文件 0x32]`，
名字按 **`mbcs`** 编码（中文目录名必须）；扩展块 `0xBEEF0004` 可以不写。
⚠️ 别按"ItemID 长度必须偶数"判 —— 正品卷条目就是 25 字节、Edge 的 IDList 总长 245，都是奇数。

|---|---|---|
| 1 | `akshare` 取数无超时 → 服务挂起 | 服务层统一 6/10s 包裹；端点测试断言超时行为 |
| 2 | 重模块冷导入 9s+ | 常驻服务启动时预热（lifespan），勿在请求内冷启 |
| 3 | 端点 20+ 超出预期 | 按 §6 分期；每期只做该期页面的端点 |
| 4 | 快讯情绪词表误判（利空判中性） | 前端展示原值 + 口径声明；词表改进单独立项，不阻塞 |
| 5 | 热榜数据源失效 | 契约内不占位；UI 保持"不可用"态直至换源验证 |
| 6 | 双轨期两套 UI 写冲突 | C5：P1 起写入口单点（Streamlit 写下线或 `web_` 前缀） |
| 7 | 磁盘旧 `latest.json` 是 repr 串 | 双格式消费已落地（C1）； league/选股页/屏幕历史全覆盖 + 测试 |
| 8 | latest 停在 10-23（周五）；10-24/10-25 为周末**非交易日**，属正常 | C3 stale 基准 = 最近应收盘交易日（非"今天"）；另需人工确认调度器健康（`system/health`） |
| 9 | SWR 把 40 秒前的价格显示成"实时价" | 旧值必须自报年龄：`data_age_seconds` + 每行 `quote_time`；看盘页 `max_stale=0` 不降级 |
| 10 | exe 里带了 `config/llm_providers.json`（含密钥） | **不分发**；要分发则用 `BIGA_LLM_PROVIDERS` / `BIGA_LLM_FEATURE_MODELS` 外置 |
| 11 | 网页端与 Streamlit 页同时点同一动作互相覆盖进度 | 任务名一律 `web_` 前缀（`progress_{task}.json` / `cancel_{task}.json` 由 task 名决定） |

开放问题（需产品决策）：① 助手页 WS 流式 vs 轮询的取舍；② 交易台真实/模拟是否合并账户视角；③ 仪表盘是否收纳复盘摘要（当前独立成页）。
